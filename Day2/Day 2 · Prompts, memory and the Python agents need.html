01Messages and roles

Every call sends a list of messages. Each message has a role: system, user or assistant.

The messages list is the whole conversation the model sees, top to bottom. system = your instructions to the model (the customer never sees them). user = what the person typed. assistant = what the model replied earlier. The model reads the whole list and writes the next assistant message.

Real world

ChatGPT's "custom instructions" and a company's support-bot settings are both just a system message added above your chat. The owner of Sweet Crumbs will never type in the chat, but her rules live in the system message of every call.

Analogy

A drama script. The system message is the director's note at the top ("you are a polite shopkeeper"). User and assistant are the two actors' lines. The model is handed the script and asked to write the next line.

03Few-shot examples: show, don't just tell

Put two or three worked examples in the messages and the model copies their pattern, format included.

Instructions alone ("classify this message") leave room for interpretation: one reply says "This looks like an order", another says "Category: Order". Your code can't use answers that change shape. Few-shot prompting adds example question–answer pairs as earlier user/assistant turns, so the model sees exactly what a correct answer looks like.

messages = [
    {"role": "system", "content": "Label the customer message with one word: order, question or complaint."},
    # three examples = "few shots"
    {"role": "user", "content": "need 2 plum cakes for friday"},     {"role": "assistant", "content": "order"},
    {"role": "user", "content": "do you have eggless?"},             {"role": "assistant", "content": "question"},
    {"role": "user", "content": "the cake was dry yesterday"},       {"role": "assistant", "content": "complaint"},
    # the real message
    {"role": "user", "content": new_message},
]

04Asking for JSON: answers your code can use

People read sentences; programs read fields. Ask the model to reply in JSON, then turn it into a Python dict with json.loads.

To save an order to a sheet, your code needs name, item, qty, date as separate fields, not a paragraph. JSON (JavaScript Object Notation) is the standard text format for that: keys in double quotes, values as text, numbers, true/false, lists or nested objects.

import json

SYSTEM = """Extract the order from the customer's message.
Return ONLY JSON, no other text, with these keys:
name (text), item (text), qty (number), date (text), eggless (true/false)."""

reply = response.choices[0].message.content     # a string that looks like JSON
order = json.loads(reply)                        # string → Python dict
print(order["item"], order["qty"])               # plum cake 2

05Memory by hand: the chat loop

To make a chatbot remember, keep a list of messages and append every question and every reply to it.

Day 1 showed that the model is stateless. Now you write the receptionist: a history list that starts with the system message, grows by two messages per turn, and is sent in full every time. Because history grows forever, real apps trim it: keep the system message plus the last few turns.

history = [{"role": "system", "content": SYSTEM}]
MAX_TURNS = 6                                     # keep the last 6 messages

def chat(user_text: str) -> str:
    history.append({"role": "user", "content": user_text})
    recent = [history[0]] + history[1:][-MAX_TURNS:] # system + last few
    response = client.chat.completions.create(
        model="openai/gpt-oss-20b", messages=recent, temperature=0.3)
    reply = response.choices[0].message.content
    history.append({"role": "assistant", "content": reply})
    return reply

06Python for agents ①: dicts and JSON

A dict stores data as key → value pairs. It is how agents hold menus, orders and messages.

MENU = {"plum cake": 500, "chocolate cake": 650, "cupcake": 80}   # key → value

MENU["plum cake"]                  # 500
MENU.get("donut", "not on menu")   # 'not on menu'  (no crash)
MENU["donut"]                      # KeyError: 'donut'  (crash!)

order = {"name": "Ravi", "item": "plum cake", "qty": 2, "eggless": True}
order["qty"] * MENU[order["item"]] # 1000

import json
text = json.dumps(order)           # dict → JSON string, to send or save
back = json.loads(text)            # JSON string → dict

You've already used dicts: every message is one ({"role": ..., "content": ...}) and messages is a list of dicts. JSON looks almost the same but is text: double quotes only, true/false/null instead of True/False/None.

07Python for agents ②: functions, type hints and docstrings

A function is a named machine: inputs in, output out. Type hints and a docstring say what goes in and what comes out.

def get_price(item: str, qty: int = 1) -> int:
    """Return the total price in rupees for qty of an item on the Sweet Crumbs menu."""
    return MENU[item.lower().strip()] * qty

08Python for agents ③: decorators, the @ sign

A decorator wraps a function to add extra behaviour, such as logging, without changing the function's code.

import functools

def log_call(func):                              # takes a function…
    @functools.wraps(func)                       # (keeps the name and docstring)
    def wrapper(*args, **kwargs):
        print(f"→ calling {func.__name__}{args}")
        result = func(*args, **kwargs)           # run the original
        print(f"← {func.__name__} returned {result!r}")
        return result
    return wrapper                               # …returns a wrapped one

@log_call                                        # same as: get_price = log_call(get_price)
def get_price(item: str, qty: int = 1) -> int:
    """Return the total price in rupees for qty of an item on the menu."""
    return MENU[item.lower().strip()] * qty

You'll meet decorators everywhere: @tool in LangChain turns a function into an agent tool (Day 4), @app.route("/") in Flask turns a function into a web page. The @ line is always "wrap this function with extra powers".

09Python for agents ④: try / except, failing politely

Things will go wrong: no internet, rate limits, bad JSON, unknown cakes. try/except catches the error and lets you reply politely instead of crashing.

from openai import RateLimitError, AuthenticationError, APIConnectionError

try:
    response = client.chat.completions.create(model=MODEL, messages=history)
    reply = response.choices[0].message.content
except RateLimitError:
    reply = "We're a little busy. Please try again in a minute."
except AuthenticationError:
    reply = "Setup problem: please tell the owner the API key isn't working."
except APIConnectionError:
    reply = "I can't reach the server right now. Please try again shortly."
print(reply)

Real world

When a UPI payment fails, the app says "Payment failed, money not debited, try again"; it doesn't close itself. A bot that crashes leaves the customer with silence. On Day 10 we go further with retries and backup models; today we learn the basic net.

Analogy

A safety net under a tightrope walker. Most of the time it's never used. When there's a slip, the show doesn't end in disaster: the walker lands safely and the audience gets an explanation.

Check yourself2 questions

1. Without try/except, what happens when the API returns a 429 rate-limit error?

An unhandled exception ends the program. (The OpenAI client does a couple of quick retries first, but if those fail, it raises.)

2. Which is the worst way to handle errors in a customer-facing bot?

except: pass swallows every error silently: the customer gets nothing and you never learn what broke.

Today's build: a Sweet Crumbs chatbot that remembers

Everything from today in one Colab cell: the menu as a dict, a system prompt built from it, a priced function with a decorator, the chat loop with trimming, and try/except so it never crashes. Run the Day 1 setup cell (install, key, client) first.

import json, functools
from openai import RateLimitError, APIConnectionError

MODEL = "openai/gpt-oss-20b"
MENU = {"plum cake": 500, "chocolate cake": 650, "cupcake": 80}

SYSTEM = f"""ROLE:   You are the friendly assistant for Sweet Crumbs Home Bakery.
FACTS:  Menu with prices in rupees: {json.dumps(MENU)}
        Orders need 24 hours' notice. All cakes have eggless versions.
RULES:  Never promise a delivery time. If it isn't in FACTS, say "I'll check with the owner."
        Remember the customer's name and order during the chat.
FORMAT: Under 50 words, friendly, English or Telugu matching the customer."""

def log_call(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        print(f"   [log] {func.__name__}{args} -> {result!r}")
        return result
    return wrapper

@log_call
def get_price(item: str, qty: int = 1) -> int:
    """Return the total price in rupees for qty of an item on the menu."""
    return MENU[item.lower().strip()] * qty

history = [{"role": "system", "content": SYSTEM}]
MAX_TURNS = 8

def chat(user_text: str) -> str:
    history.append({"role": "user", "content": user_text})
    recent = [history[0]] + history[1:][-MAX_TURNS:]
    try:
        response = client.chat.completions.create(model=MODEL, messages=recent, temperature=0.3)
        reply = response.choices[0].message.content
    except RateLimitError:
        reply = "We're a little busy. Please try again in a minute."
    except APIConnectionError:
        reply = "I can't reach the server right now. Please try again shortly."
    history.append({"role": "assistant", "content": reply})
    return reply

print("Total for 6 cupcakes:", get_price("cupcake", 6))
while True:
    text = input("You: ")
    if text.lower().strip() in ("bye", "exit", "quit"):
        print("Bot: Thank you for visiting Sweet Crumbs!")
        break
    print("Bot:", chat(text))
